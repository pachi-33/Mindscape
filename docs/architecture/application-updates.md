# 应用生命周期与更新：现状设计

## 职责与边界

应用入口和全局模型负责窗口、当前文档库、失活/退出保存以及首启提示协调。更新子系统负责偏好、版本检查、展示状态以及保存与安装交接。Sparkle 负责下载验签、替换应用和重新打开。

| 类型 | 职责 |
|---|---|
| [MindscapeApp](../../Mindscape/App/MindscapeApp.swift) | 创建主窗口、设置场景、菜单栏入口和共享 AppModel |
| [AppModel](../../Mindscape/App/AppModel.swift) | 打开存储、回退并提示、维护当前编辑器，在失活/退出时发起保存 |
| [RootView](../../Mindscape/Views/RootView.swift) | 根据当前编辑器选择工作区或空状态，连接 Agent 和首启提示流程 |
| [UpdateChecker](../../Mindscape/Support/UpdateChecker.swift) | 管理检查偏好、通道、提醒、进度和安装许可，并接入 Sparkle |
| [UpdateWindow](../../Mindscape/Views/UpdateWindow.swift) | 展示版本、进度与错误，提供更新和人工下载入口 |

## 生命周期

`AppModel` 初始化时读取外观偏好、尝试创建 `DocumentStore`、加载目录和文档，并监听应用失活与终止通知。自定义目录不可用时回退默认目录；没有可用磁盘库且内存库创建成功时使用内存库并提示。`RootView` 稳定后依次处理更新授权与 Agent 引导，再结束首次提示协调。更新可用且横幅未隐藏时，工作区覆盖层显示横幅；横幅也会自动隐藏。

`saveForUpdate()` 在安装交接前提交当前节点文字，通过编辑器的同步保存入口获取磁盘写入结果。文稿仅在内存中或写入失败时，协调器取消已准备的安装。退出请求在更新会话期间经过同一保存规则。

## 更新检查

- 自动检查初始默认关闭，第一次通过首启询问保存偏好。启用后启动时检查一次，之后按 24 小时节流。手动检查可以绕过时间限制。
- 更新目录和版本化 ZIP 来自自有仓库。稳定版只检查正式通道，预发布版还可发现 beta。旧版缓存、ETag 和跳过版本状态不参与新源检查。
- 后台检查只展示可用版本。点击「更新」后，Sparkle 重新确认候选并下载。失败时窗口显示错误和重试操作。

## 签名与安装

Sparkle 验证更新目录和归档签名，在应用确认保存完成后接管退出、替换和重启。项目维持现有 bundle ID 和独立文稿库路径。正式构建、公证、更新目录生成和首次手动迁移见[发布说明](../releasing.md)。

## 验证

[UpdateCheckerTests.swift](../../MindscapeTests/UpdateCheckerTests.swift) 验证检查偏好与节流、候选版本、保存失败和验签错误处理。真实替换和重启需要用隔离库以及两份已签名应用复验。

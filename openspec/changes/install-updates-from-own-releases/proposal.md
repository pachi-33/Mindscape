# Proposal

## Why

当前客户端从上游仓库检查更新，无法发现我们在 `pachi-33/Mindscape` 发布的版本。用户下载更新后还要手动替换应用，保存失败也不会阻止退出。

## What Changes

- 从自有仓库的发布渠道检查更新。稳定版与预发布版继续按各自通道发现兼容的新版本，后台检查沿用用户偏好。
- 用户点击「更新」后，应用下载并验证更新包，在确认当前导图已保存后安装新版并重新打开。
- 下载、验签或保存失败时停止更新，保留当前版本并提供下一步操作。安装位置不可写或用户取消系统授权时，说明原因并提供手动安装入口。
- **BREAKING**：已有客户端只认识上游更新源，需要手动安装一次包含新更新器的过渡版本。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `application-updates`：切换更新源、增加用户发起的自动安装与重启、要求更新包验签和安装前保存。

## Impact

- 更新菜单、设置、启动检查和发布脚本将使用同一套发布配置，并引入 Sparkle 2。
- 应用和更新包的正式分发需要签名材料。包含新更新器的版本沿用现有应用标识和文稿库。

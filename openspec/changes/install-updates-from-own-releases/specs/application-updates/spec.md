# Spec Delta

## ADDED Requirements

### Requirement: 从自有仓库发现并获取更新

客户端 SHALL 从 `pachi-33/Mindscape` 的发布渠道发现更新。客户端 SHALL 只将该仓库已发布、版本高于当前安装且与当前系统及通道兼容的版本作为更新候选。更新包和手动安装入口 SHALL 指向该仓库的发布内容。

#### Scenario: 自有仓库发布新版本

- **GIVEN** 用户已安装包含新更新器的版本
- **WHEN** 用户检查更新且自有仓库发布了兼容的新版本
- **THEN** 应用显示该版本并提供「更新」操作

#### Scenario: 仓库暂无可安装的新版本

- **WHEN** 自有仓库没有符合条件的发布，或者只有草稿、当前版本或更旧版本
- **THEN** 应用说明暂无可用更新，不提供安装操作

#### Scenario: 迁移后首次检查更新

- **GIVEN** 已有客户端留下了来自上游仓库的缓存或跳过版本记录
- **WHEN** 用户首次运行过渡版本并检查更新
- **THEN** 应用只使用自有仓库的发布信息，保留自动检查偏好

### Requirement: 确认更新后安装并重新打开应用

用户点击「更新」后，应用 SHALL 下载并验证候选更新，在退出前结束当前就地编辑并确认数据已写入文稿库，然后安装新版并重新打开。后台检查 SHALL 只提示可用更新。

#### Scenario: 完成一次更新

- **WHEN** 用户点击「更新」，下载、签名校验、保存及安装均成功
- **THEN** 应用显示更新进度，退出旧版，安装并重新打开新版，原有导图与文稿库可继续使用

#### Scenario: 后台发现新版本

- **WHEN** 后台检查发现可用版本而用户尚未点击「更新」
- **THEN** 应用提示可用版本，等待用户操作，当前应用继续运行

#### Scenario: 保存失败

- **WHEN** 当前编辑无法提交、写入磁盘失败，或未保存的编辑仅存在于内存文稿库
- **THEN** 应用中止本次安装，保留当前进程和编辑内容，提示保存失败及重试方式

#### Scenario: 下载失败或用户取消

- **WHEN** 下载中断或用户在替换前取消更新
- **THEN** 当前版本保留，用户可以重试

#### Scenario: 安装位置限制或授权取消

- **WHEN** 当前应用位置不可写且系统授权未能取得，或用户取消授权
- **THEN** 当前版本保留，应用说明原因并提供自有仓库的手动安装入口

### Requirement: 安装前验证发布签名和应用身份

应用 SHALL 验证更新包的发布签名和新版的应用身份。出现缺失、篡改或不可信时 SHALL 拒绝安装。

#### Scenario: 下载文件通过验证

- **WHEN** 下载文件的发布签名有效，且新版的应用标识和签名身份符合预期
- **THEN** 更新器允许继续执行安装前保存检查

#### Scenario: 下载文件被修改

- **WHEN** 下载内容与有效的更新签名不匹配，或新版应用身份不符合预期
- **THEN** 应用报告校验失败并保留当前版本

#### Scenario: 无法取得有效签名

- **WHEN** 下载文件缺少签名，或更新器无法建立签名信任
- **THEN** 应用报告有效签名缺失或不可信，阻止退出和替换

## MODIFIED Requirements

### Requirement: 根据已安装版本选择更新通道

应用 SHALL 根据已安装版本是否为预发布版本选择自有仓库的更新通道。

#### Scenario: 已安装稳定版

- **WHEN** 已安装版本没有预发布标识
- **THEN** 检查器只提供正式版本

#### Scenario: 已安装预发布版本

- **WHEN** 已安装版本带有预发布标识
- **THEN** 检查器允许从正式版本和符合预发布通道的版本中选择更新

## REMOVED Requirements

### Requirement: 下载后处理校验结果

**Reason**：旧流程允许在缺少 SHA-256 时继续使用下载包，不能作为自动安装的信任依据。

**Migration**：通过「安装前验证发布签名和应用身份」验收应用内更新。人工下载的安装包仍可提供 SHA-256 供用户核对。

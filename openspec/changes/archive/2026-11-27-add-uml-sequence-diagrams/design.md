# Design

## Context

MindMap 作为 Codable JSON 存入 SQLite 的 documents.content，MapEditor 管理撤销和延迟保存。既有的 MapLayout、树渲染器和节点 API 假定父子关系。时序图需要一组横向生命线和纵向有序事件。

## Goals / Non-Goals

设计目标是让普通用户和本地 Agent 能从空白共同使用同一种文档格式。首版聚焦可编写、可预览、可复核的时序语义。完整 UML 元模型、XMI 互通、自动分析 Python 代码和分布式性能测量留待独立设计。

## Decisions

1. 模板使用 `sequence`。MindMap 的可选字符串 `sequenceSource` 是持久化原文，缺失表示旧树形文档，空字符串表示空白时序图。树和时序图各自拥有工作区。Undo、保存、快照和目录沿用现有文档机制。
2. 持久化与 Agent 交换采用内部行式记法，显式声明 `participant R0 as Scheduler 0`。发送 `A->>B: 调用`、`A-)B: 投递`、`B-->>A: 返回`，同端点表示自调用。支持 `Note over A,B: 说明`、`activate/deactivate A` 和可嵌套的 `loop/opt/alt/par`、`else/and`、`end`。可接受 sequenceDiagram 标头；该语法的范围由此文档和测试定义。按行报告未声明端点、不匹配的块或激活；网关传入的未完成草稿也保留。
3. Swift 本地解析为顺序事件。图形编辑画布与 PDF、PNG 共享排版、标签换行和绘制实现。长图可滚动浏览，文档 JSON 可再次导入。树形专属格式或操作须使用类型判断，避免输出貌似成功的空图。
4. 网关沿用 POST /v1/maps、PATCH /v1/maps/{id}、GET 及 export。PATCH 的 sequenceSource 替换当前原文。新建、回读和重复编辑同一 ID 组成端到端写入测试。客户端用认证的回环接口，复用现有文档同步。
5. 验收依据固定在 SGLang v0.5.17 的 29481685462732237d80d86076d6563e1f658102。图上注明配置、条件和索引。独立审阅者先看导出的图，后读对应源码，核对结论保存在测试记录中。[上游源码](https://github.com/sgl-project/sglang/blob/29481685462732237d80d86076d6563e1f658102/python/sglang/srt/managers/scheduler_pp_mixin.py)

## Risks / Trade-offs

- 有效预览依赖成对的控制片段。保留草稿并定位错误，方便用户分步输入。
- 四个调度器同时推进，各自的局部顺序和不同微批之间的重叠容易被误读。样例须显式说明调度槽、相邻传送、环回与已启动工作之间的依赖。
- 单页矢量图可以放大阅读。图中文字须换行并避开箭头、同一行的激活和相邻生命线，测试时直接渲染并检查。

## 实现边界与状态一致性

- SQLite v3 为文档和快照添加类型索引，旧行默认为树形文档。列表可识别类型，正文仍只在 content JSON 中保存。解析失败只影响预览，保存、撤销和快照保留原文。
- 预览支持 24 条生命线、600 个事件、16 层片段或激活、128 KiB 源码。单条标签最多 256 个字符且不超过 1 KiB。超过解析范围时显示诊断。PNG 在分配位图前限制为 3200 万像素、单边 32768 像素。
- 网关对已打开的时序图执行写入前验证，读取最新编辑器草稿后再更改指定字段。在同一次 SQLite 更新中处理文档字段与目录变动，刷新时取消旧编辑器的待保存任务。
- SwiftUI 承载可交互的 AppKit 画布与图形属性表单。原生绘图从同一几何布局进行命中测试和屏幕、PDF、PNG 绘制。

## 图形编辑设计

用户选择生命线或有序事件，使用属性控件修改名称、端点、消息种类、片段和守卫。图形操作统一生成有效编辑并提交到 MapEditor 的撤销与保存路径。插入位置区分片段外部、片段内部和分支，容器编辑按完整结构处理。内部稳定参与者 ID 独立于显示名，重命名保持连线引用。图形画布与导出共享文档的 MapTheme，选择及连线过程的反馈属于编辑器状态。

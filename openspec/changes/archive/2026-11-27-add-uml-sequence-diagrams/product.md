# 产品需求与 UML 调研

## 用户与工作场景

一名开发者在 Mindscape 本地文档库中解释四个调度器的通信；另一人只拿到导出的图和上游源码，需要判断方向、守卫和处理顺序。两人应能区分请求、张量、共识以及本地计算，并能通过导入继续修订图。

## UML 时序图由什么组成

依据 OMG UML 2.5.1 第 17 章 Interactions、第 17.8 节的时序图记法及表 17.1、17.2 整理。符号传达的是事件之间的顺序，默认纵向距离不表示耗时。[OMG UML 2.5.1](https://www.omg.org/spec/UML/2.5.1/PDF)

| 元素 | 读图时回答的问题 | 本次产品约定 |
| --- | --- | --- |
| 交互及参与者生命线 | 哪些角色或实例参与交互？ | 文档标题命名交互，参与者横向排列，虚线向下延伸。标识符与显示名分开。 |
| 消息及其收发事件 | 谁发给谁，如何调用，在哪里返回？ | 实线实心箭头表示同步，实线开放箭头表示异步，虚线回复；同一生命线可以折返自调用。 |
| 执行规格 | 一个参与者在哪段交互中执行行为？ | 激活条由起止标记界定，与消息配合。 |
| 组合片段、操作数和守卫 | 哪些步骤有条件、可替代、重复或并发？ | 支持 opt、alt/else、loop、par/and，允许嵌套，名称和条件贴在相应框或分隔处。 |
| 注释 | 哪些假设或索引需要读者知道？ | 允许在单条或多条生命线上写备注。 |
| 其他 UML 交互元素 | 如何表示对象创建、销毁、门、交互引用、状态不变量、时间和时长约束？ | 调研记录这些标准元素；首版定义的输入语法见设计。 |

## 创作与验收

1. 从“新建导图”选“UML 时序图”，看到可直接添加参与者的空画布。通过画布、按钮和属性表单创建、选择、命名、重排和删除生命线、消息、备注、激活和嵌套片段。用户只输入名称、守卫和说明。
2. 同一画布即时呈现修改。点击生命线、连线或片段后能调整属性。UI 维护配对关系，撤销、重做、切换或退出后可恢复图元和顺序。
3. 导出 PDF 供独立阅读，PNG 供图片分享，JSON 供导入后修改。对于很长的图，文本换行且可放大阅读。
4. 验收者在新建的空白图上，仅用用户可见的图形控件创建完整 PP4 案例，网关用于回读、核验或导出。独立审阅者只用最终成图和固定上游源码核对调度。

### 验收的边界

样例限定分离式 prefill、PP=4。描述四个进程的局部事件与跨槽传递，给出深度为零和大于零时的处理位置。图是源码级调度说明，性能测量需要单独设计实验。


## 视觉一致性

时序图与普通思维导图共用文档主题、明暗外观、画布背景与网格、节点配色、连接线与选中高亮。参与者画成横向排列的圆角卡片，保留 UML 生命线、顶部标签、消息箭头和组合框。属性面板、工具栏和缩放控件遵循已有工作区交互。切换主题后，预览、保存重开和图形导出使用同一主题。
